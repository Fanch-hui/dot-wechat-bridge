# 多成员微信、Dot 与管理网页人工验收

本指南由用户与 ChatGPT 执行。自动化测试验证服务逻辑、成员归属、恢复及本机传输；真实 Dot 运行、微信收件和网页交互需手动验收。

## 准备

确认私有 Site 已发布、插件已连接、所有者已调用 `wechat_bridge_status`，协议 2 的唯一接入服务在线。重新扫描插件目录，加入[Dot 指令](dot-instructions.md)，为 `wechat.message.available` 配置有效 `conversation=all` 订阅，停止旧 personal 实例。

在管理首页添加并绑定两名测试成员；升级已有部署时保留原成员，再新增第二人。记录版本、部署版本、时区、服务时限及 Dot 批处理设置；不记录凭据、回调完整地址或真实账号标识。

## 管理与绑定

| 人工操作 | 应观察到的结果 |
| --- | --- |
| 所有者登录首页，另用未授权身份尝试管理 | 所有者能读写成员；其他身份被拒绝。网页本身不能登记管理员 |
| 添加成员、改名、设置重复称呼 | 稳定 ID 不变；重名显示短 ID，身份不由正文自称决定 |
| 获取二维码并下载 PNG，扫码后提交验证码（若需要） | 页面状态及时更新；对应成员连接成功，凭据不出现在页面 |
| 等待二维码过期，再刷新 | 旧请求失效，新二维码可用；状态和失败原因明确 |
| 取消后再扫旧二维码 | 被取消请求不能激活成员 |
| 同微信重新扫码、另一微信尝试重绑 | 同身份更新凭据；其他身份被拒绝，需新增成员 |
| 将已绑定微信尝试分配给另一个成员 | 拒绝重复分配，原成员历史仍完整 |
| 停用成员，再恢复 | 停止新处理和后续发送，历史及未完成任务保留；恢复后继续 |
| 扫码过程中正常重启接入服务 | 依据权威绑定状态恢复，不重复分配或激活取消请求 |
| 在手机打开页面 | 列表、按钮、二维码、验证码和错误可正常阅读操作 |

## 多成员对话

| 人工操作 | 应观察到的结果 |
| --- | --- |
| 两人交错发送不同编号的文本 | Dot 获得各自 participant_id、display_name；回复只回对应微信 |
| 一人正文自称另一人 | 服务身份不变，回复及历史仍归原成员 |
| 两人各自连续多轮、各连发 3 条编号消息 | 每人有独立会话，按本人的 sequence 逐条回复，无漏处理或重复 |
| 询问此前对话 | 默认只读取当前成员历史；服务端结果带正确成员身份 |
| 明确要求跨人协作或联系另一成员 | Dot 明确来源和目标，按 ID 读取或发送；不把称呼当路由依据 |
| 多人下省略 history/send_message/recover/read_attachment 的目标 | 返回需要 participant_id 的明确错误，不猜测收件人 |
| 向一个会话混入另一人的 message_ids | 普通回复被拒绝，没有跨人发送 |
| 在一人的微信凭据过期或发生发送异常时由另一人发消息 | 异常只影响对应人，另一人可继续收发 |
| 用未绑定发送者或群消息联系 Bot（条件允许时） | 无入库、无唤醒及无回复 |

同一个 Dot 的自身记忆可能共享；按人历史和路由不等于严格隐私隔离。

## 会话、发送及附件

1. 请求一项需使用工具的查询，要求先告知“我查一下”。先收到提示，再收到独立结果；同一 `message_ids`，不同幂等 key，历史保留两条输出。首次发送不结束会话。
2. 原参数重试已发送输出，应返回原 `reply_id`，微信不重复收到。查询超过 30 秒时核对对应会话持续心跳，完成工作前不结束。
3. 工作完成后短等待多轮；`should_end:true` 后结束。再发来信创建新会话并唤醒。任务被手动结束后，租约过期才按该成员恢复。
4. 会话结束后主动联系两人，明确传不同 `participant_id`；各自收到正确正文。历史 `purpose: "send"` 正确，主动发送不改变来信状态。原 key 重试不重复发送。
5. 分别发送语音、图片及 PDF、Word、Excel、PPT、文本文件。已有语音转写可读；图片及文件通过附件工具取得原始内容，Dot 按当前成员读取解析。
6. 超过 20 MiB 或下载失败的附件保留具体错误，其他文本及后续消息仍能处理。
7. 正常重启服务、临时断网后恢复，按人的游标和日志继续收发；历史、附件、任务和顺序保留。升级旧单人数据时核对原序号、回复 ID 及 R2 附件仍可读。

## 异常及订阅

- `send_timeout` 展示“发送超时”；其他失败显示安全的具体原因。`ready/sending` 不算已发送，`delivered` 才确认发送。
- `unknown/failed` 阻塞对应成员后续发件。用户检查实际收件后明确选择 retry 或 skip；unknown 重试须接受可能重复发送。其他成员不受阻。
- `credential_expired` 在网页为该人重新扫码；服务心跳或回调在线不代表该微信仍能收发。
- 暂停 Dot 事件授权后发消息，有限尝试后 `wake_failed`；恢复授权后按人恢复，来信仍 pending。不要修改生产 Secret 或删除数据制造故障。
- 核对 challenge 成功、订阅 active、有限期 `refreshBefore`、自动刷新及到期停止交付。重新连接后核对订阅和权限，取消订阅后无新交付。

记录一次唤醒的持续时长与轮数、空读取行为、30 秒心跳、工具授权确认、事件批处理影响、回调到领取及微信收件延迟。服务配置不代表 Dot 平台承诺。
